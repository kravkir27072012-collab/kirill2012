# KrossKZ — агрегатор кроссовок по маркетплейсам Казахстана

Поиск лучшего варианта кроссовок сразу по нескольким маркетплейсам Казахстана
(Kaspi.kz, Technodom, Mechta, Wildberries KZ, Ozon KZ): сравнение цены,
рейтинга, отзывов и эвристическая оценка риска подделки, со смысловым
скорингом «лучшего выбора», а не просто сортировкой по цене.

## Стек

- **Next.js 16** (App Router, Server Components)
- **React 19**, **TypeScript**
- **Tailwind CSS v4** + **shadcn/ui** (Radix primitives) — iOS-style дизайн
- **Zustand** — клиентское состояние (фильтры, избранное, история поиска)
- **framer-motion** — анимации карточек и списков
- **next-themes** — светлая/тёмная тема

## Запуск

```bash
npm install
npm run dev
```

Приложение поднимется на [http://localhost:3000](http://localhost:3000).

Других команд для запуска не требуется — все данные о товарах генерируются
детерминированным мок-слоем на старте (см. «Данные» ниже), без внешних API
и без базы данных.

Прочие скрипты:

```bash
npm run build   # production-сборка
npm run start   # запуск production-сборки
npm run lint    # ESLint
```

## Архитектура

```
src/
  types/marketplace.ts       — общие домейн-типы (Product, ScoredProduct, SearchFilters, ...)
  lib/
    mock/                     — мок-каталог кроссовок и генератор объявлений (детерминированный RNG)
    providers/                — MarketplaceProvider — контракт источника данных
      mock/                   — по одному мок-провайдеру на маркетплейс
      registry.ts             — единая точка регистрации провайдеров
    search/textSearch.ts      — токенизация и нечёткий текстовый поиск
    scoring/
      score.ts                — взвешенный скоринг «лучшего выбора» (цена/рейтинг/отзывы/доверие)
      authenticity.ts         — эвристика риска подделки
      applyFilters.ts         — фильтрация + сортировка уже посчитанного списка
      rank.ts                 — единая точка входа: Product[] -> ScoredProduct[]
      defaultFilters.ts        — дефолтные границы фильтров для набора товаров
    services/
      aggregator.ts           — параллельный fan-out запроса по всем провайдерам
      recommendations.ts      — подборка для главной страницы
  store/                      — Zustand: фильтры, избранное, история поиска (persist в localStorage)
  components/
    search/                   — Hero, SearchBar, ResultsView, FiltersPanel, SortControl, ...
    product/                  — ProductCard, ProductGrid, ComparisonRow, скелетоны
    shared/                   — бейджи маркетплейса/аутентичности, рейтинг, заглушка изображения
    layout/                   — Navbar, ThemeProvider/Toggle
    ui/                       — shadcn/ui примитивы
  app/
    page.tsx                  — главная: Hero + рекомендации
    results/page.tsx          — результаты поиска (+ loading.tsx со скелетоном)
    product/[id]/page.tsx     — карточка товара со сравнением цены по всем маркетплейсам
    favorites/page.tsx        — избранное
```

Ключевая идея слоя данных: UI и скоринг работают только с нормализованным
`Product[]`/`ScoredProduct[]` и никогда не знают, что данные сейчас
сгенерированы мок-провайдерами. Чтобы подключить реальный маркетплейс,
достаточно реализовать интерфейс `MarketplaceProvider` (`lib/providers/`) и
зарегистрировать его в `registry.ts` — остальной код не меняется.

## Данные

Каталог из ~15 моделей кроссовок (`lib/mock/catalog.ts`) детерминированно
разворачивается в ~45 объявлений на разных маркетплейсах (`lib/mock/listings.ts`):
цена, рейтинг продавца, отзывы и флаг официального магазина генерируются
seeded-RNG (без `Math.random`/`Date.now` в самих данных), поэтому результат
идентичен на сервере и клиенте и стабилен между запусками.

## Скоринг и риск подделки

- **Скоринг «лучшего выбора»** (`lib/scoring/score.ts`) — взвешенная сумма
  нормализованной цены, рейтинга, лог-масштабированного числа отзывов и
  доверия к продавцу, со штрафом за риск подделки.
- **Риск подделки** (`lib/scoring/authenticity.ts`) — эвристика на основе
  отклонения цены от медианы по этой же модели на других маркетплейсах,
  рейтинга продавца и числа отзывов. Официальные магазины помечаются
  «Оригинал вероятен» без дополнительных проверок. Оценка явно подаётся
  пользователю как предположение, а не гарантия.

## Известные ограничения (mock-режим)

- Данные не из реальных API маркетплейсов — это детерминированный мок-слой,
  спроектированный так, чтобы реальные интеграции подключались без изменений
  в UI/скоринге.
- Эвристика риска подделки — индикатор, а не верификация продавца.
